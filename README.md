# Mini-Z Virtual Drift Circuit

iPad を机に水平に置き、その画面に 1/28 の RC カー (京商ミニッツ、MRD ZERO など) を載せて遊ぶ Web アプリです。
画面には真上から見たサーキットを描き、**仮想車両の動きに合わせて路面全体を動かす**ことで、静止した実車がサーキットを走り、ドリフトしているように見せます。

- 仮想車両が自動でコースを周回し、ストレートで加速、コーナーで減速してドリフト、S 字で振り返し、脱出でグリップ回復
- 車体は画面の基準位置 (既定: 幅 50% / 高さ 60%) に固定され、車体の前方が常に画面の上
- 既定では仮想車両を描かない (デバッグ用にだけ表示)
- バックエンド・外部 API・ログイン不要。静的ファイルだけで動く

## iPad での使い方

1. iPad の Safari で公開 URL を開く: **https://volpe28v.github.io/mini-z-virtual-circuit/**
2. 共有ボタン → **ホーム画面に追加**。ホーム画面のアイコンから起動すると、ブラウザの UI が消えたスタンドアロン表示になります
3. iPad を机に水平に置き、画面の長辺を RC カーの長辺に合わせて車体を載せる (車体の前方 = 画面の上)
4. 左上のボタンで操作する
   - ☰ 設定パネル (右端に開く) / ⏸ 再生・停止 / 目のアイコン UI 非表示
   - UI を非表示にした後は、**画面の左右の端 (幅 28px) をタップ**すると再表示されます
5. 最初に **実寸キャリブレーション** を行う (設定 → 「実寸キャリブレーション (100mm)」)
   - 画面に 100mm の線が出ます。定規を当てて、実寸と一致するように ＋/− かスライダーで調整し「完了」
   - 結果は保存され、次回以降も使われます
6. 速度、最大ドリフト角度、ドリフト強度、コース幅、車両位置、路面の明るさなどはパネルでリアルタイムに調整できます。設定は端末に保存されます

> 画面の実寸は機種で違います。既定値は画面幅からの推定 (iPad mini = 6.42px/mm、それ以外の iPad = 5.2px/mm) なので、必ずキャリブレーションしてください。
> 車体の位置は「設定」の車両位置 X / Y で動かせます。車体が実際に載る位置に合わせてください。

## 設定項目

| 項目 | 内容 | 既定 |
|---|---|---|
| 走行速度 | 最高速 (mm/s)。コーナーでは自動で減速 | 600 |
| 最大ドリフト角度 | 車体の向きと進行方向の最大差 (0〜60°) | 35° |
| ドリフト強度 | ドリフトの出方と応答の速さ (0〜2) | 1.0 |
| コーススケール | コース全体の倍率 | 1.0 |
| コース幅 | 路面の幅 (mm) | 119 |
| 車両位置 X / Y | 車体を置く画面上の位置 | 50% / 60% |
| 路面の明るさ | 実物の車体との明るさ合わせ | 1.0 |
| タイヤスモーク | ドリフト中に後輪から出る煙の量 (0〜3、0 でオフ)。ドリフト角が 15° を超えると出て、深いほど多く濃い | 1.0 |
| モーションブラー | 前フレームの残像の強さ | 0.2 |
| 車両の長さ / 幅 | デバッグ表示の輪郭と、車輪の位置・大きさ (車体の寸法に比例) | 150 / 70 mm |
| 描画解像度 | 重いときに下げる | 1.0 |
| 重いときは解像度を自動で下げる | フレームレートが 50fps を下回ったら、描画解像度を段階的に (最小 ×0.5) 下げる。結果は端末に保存され、設定のリセットで戻る | オン |
| 仮想車両を表示 | デバッグ用 (輪郭・車輪・車体向き = 白、進行方向 = 水色) | オフ |

## ローカルでの起動

ビルドは不要です。静的ファイルを配信するだけです (ES Modules と Service Worker のため `file://` では動きません)。

```sh
npm start            # python3 -m http.server 8765 --bind 127.0.0.1
# → http://127.0.0.1:8765/
# コース全体の俯瞰 (コース形状の確認用): http://127.0.0.1:8765/?overview
```

テスト:

```sh
npm test             # node --test tests/*.test.mjs (Node 20 以上。依存パッケージなし)
```

## 実装概要

詳しくは [docs/design.md](docs/design.md)、作業の分割は [docs/tasks.md](docs/tasks.md)。

- `js/track.js` — 提供されたコース図 (①〜⑨) をなぞった制御点を Catmull-Rom でつなぎ、平滑化して 4mm 間隔に再サンプル。曲率と速度プロファイルを事前計算。走行は曲線パラメータでなく**弧長**で進める (速度ムラなし、周回の継ぎ目なし)
- `js/vehicle.js` — 位置・速度・車体の向き・進行方向・ドリフト角を独立に管理。ドリフト角は 2 次ばね + 角速度上限で、S 字では符号が滑らかに反転 (振り返し)
- `js/camera.js` — `画面 = アンカー + k·Rot(−π/2 − heading)·(ワールド − 車両位置)`。行列で回すので ±180° の折り返し問題が起きない
- `js/textures.js` — 路面・芝・砂利を周期ノイズで生成し、**ワールド座標に固定した CanvasPattern** として塗る (ちらつかない)。色むらはタイルに焼き込み、路面と芝は毎フレーム 1 回の塗りで済ませる
- `js/marks.js` — 車両ロジックそのものを基準走行させ、ドリフト中の後輪軌跡からタイヤ痕を作る
- `js/smoke.js` — タイヤスモーク。ドリフト中に後輪の位置から粒を出し (固定長のリングバッファ、最大 300 粒)、ワールド座標に固定して尾を引かせる。1 枚のスプライトを拡大縮小して描く
- `js/renderer.js` — 路面・縁石・ランオフ・白線を事前に Path2D 化。モーションブラーは前フレームの残像 (Safari 非対応の `ctx.filter` は使わない)
- `sw.js` — ネットワーク優先 + オフライン時はキャッシュ。相対パスなのでサブディレクトリ配信で動く

## パフォーマンス

- 毎フレームの大きな塗りは「芝」「路面」の 2 回だけ (色むらはタイルに焼き込み済み)。路面・縁石・白線・タイヤ痕は設定変更時に Path2D を作って使い回す
- `backdrop-filter` (背景のぼかし) は、毎フレーム更新される canvas の上で iOS を重くするので使わない
- 実測 (PC の Chromium、ソフトウェア描画、768×1024 / dpr 2 相当): 1 フレームの描画時間を 47ms → 22ms に短縮 (層ごとの強制フラッシュ込みの目安。iPad の実測ではない)
- それでも 50fps を下回る端末では、描画解像度を自動で下げる

## タイヤスモークについて

- 煙は画面の路面に描くものなので、**実物の車体に隠れる部分は見えません**。見えるのは、車体の左右と後ろにはみ出した部分です
- 煙が車体の脇に見えるよう、外側へ広がり、車と一緒にしばらく進む動きにしてあります
- 実物の車体の上に被さるような表現はできません (画面より手前に車体があるため)
- 描画コストは、量 1.5 (約 130 粒) で PC のソフトウェア描画 1 フレームあたり約 +8ms。量 3 (最大約 260 粒) ではその 2 倍近くになります。重いときは量を下げるか 0 にしてください (自動の解像度調整も効きます)

## 既知の制約 (未検証を含む)

次は**実機でしか確認できていません** (未検証):

- iPad Safari での 60fps (確認したのは PC の Chromium のみ。重ければ「描画解像度」を下げるか「モーションブラー」を 0 にする。自動調整は 50fps 未満で働く)
- 実物のミニッツを載せたときの縮尺・明るさ・ドリフトの見た目の自然さ (ばねの係数などは設定の「ドリフト強度」で調整できるが、既定値の妥当性は実機で要確認)
- ホーム画面からのスタンドアロン起動、Screen Wake Lock の動作、機内モードでのオフライン起動 (キャッシュされることは確認したが、オフラインでの起動そのものは未確認)
- モーションブラーの見た目 (残像方式)

その他:

- Screen Wake Lock は対応環境 (iOS 16.4 以降) のみ。非対応の環境では、iPad の「自動ロック」を「なし」にしてください
- 画面の実寸は機種ごとに推定値を使うため、初回にキャリブレーションが必要
- コースは 1 種類のみ (提供されたコース図をなぞったもの。複数コース、夜間、ウェット、音などは対象外)。図の手描きの形を拡大してなぞっているので、細部は図と完全には一致しない
- 走行は自動周回のみ。物理シミュレーションではなく、見た目を優先したドリフト表現
- UI の非表示状態は保存しない (再読み込みで UI が戻る)
- 画面を縦長以外にしても動くが、縦画面 (Portrait) 前提の調整
- 検索エンジンには載せない設定 (`noindex`、`robots.txt`)。アクセス制限はない
