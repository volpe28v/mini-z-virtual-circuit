# 設計書: Mini-Z Virtual Drift Circuit

## 1. 目的とコンセプト

iPad を水平に置き、その上に 1/28 の RC カー (京商ミニッツ等) を載せる。画面には真上から見たサーキットを描き、
**仮想車両の動きに合わせて路面全体を移動・回転させる**。実車は静止したまま、サーキットを走ってドリフトしているように見える。

- 車体は画面上の基準位置 (既定: 幅 50% / 高さ 60%) に固定し、車体の前方は常に画面の上を向く
- 走行感はすべて背景の移動と回転で表現する
- 既定では仮想車両を描かない (実車があるため)。デバッグ用にだけ輪郭を出す
- 静的ホスティング (GitHub Pages) のみ。バックエンド・外部 API・ログイン無し

## 2. 非ゴール (初期バージョン)

複数コース、屋内/峠/市街地、夜間、ウェット、音 (合成を試したが実車の質感に届かず削除)、ゲームパッド/プロポ連携、手動走行、コースエディタ、走行パターン選択。

## 3. 技術選定

| 項目 | 選択 | 理由 |
|---|---|---|
| 言語 | JavaScript (ES Modules)、ビルド無し | 依存ゼロ。GitHub Pages にそのまま置ける |
| 描画 | Canvas 2D | 要件どおり。PixiJS は不要 |
| テスト | `node --test` (純粋ロジック) + Playwright (ブラウザ) | 依存を増やさない |
| PWA | manifest + Service Worker (ネットワーク優先 + オフライン用キャッシュ) | オフライン再生、ホーム画面追加 |
| 公開 | GitHub Pages (main ブランチ直下) | 設定が最小 |

## 5. 座標系と単位

- ワールド座標は **mm** (実物の 1/28 モデル上の寸法をそのまま画面上の mm とみなす)。y は下向き
- 角度は `atan2(y, x)` 基準 (東 = 0、時計回りが正)。**左コーナー = 角度が減る = 曲率 κ < 0**
- 画面倍率 `k = pxPerMm × courseScale` (CSS px / mm)
  - `pxPerMm`: キャリブレーションで決まる、画面の実寸 (既定は画面幅からの推定: 744px 幅 → 6.42、768px 幅以上 → 5.2、それ以外 → 3.78)
  - `courseScale`: コース全体の拡大縮小 (既定 1.0)

## 6. コース

### 6.1 形状

ユーザー提供のコース図 (①〜⑨ の番号付き、図の START はメインストレート上) をなぞった制御点 (図の px 座標、y 下向き) を、centripetal Catmull-Rom スプラインで閉ループにつなぐ。
図の 1px = 6.5mm に拡大し、ガウス平滑 (σ=40mm) でなめらかにしてから等間隔 (4mm) に再サンプルする。始点と終点は同じ点なので、継ぎ目は出ない。

走行方向は図の番号順 (①→⑨)。START の下の直線を左向きに走るので、**全体は時計回り** (右コーナーが主、曲率 κ > 0)。

| 区間 | 内容 |
|---|---|
| START〜① | メインストレート (約 1.7m、S/F ライン) から、左下の右コーナーで左辺を北へ |
| ② | 左辺の山形 (右→左の連続コーナー) |
| ③ | 斜めに上がり、北へまっすぐ |
| ④ | 上へ大きく膨らむ右コーナー |
| ⑤ | 斜めの長い直線と、途中の小さな左右の段 |
| ⑥ | 右端のヘアピン (右 約 170°、R≈190mm) |
| ⑦ | 折り返した後の緩い曲がり |
| ⑧ | 斜めの下りと、左側の左コーナー |
| ⑨ | 右下の右 180° コーナーからメインストレートへ |

全長は約 13.1m、最小半径は約 166mm (コース幅の上限 180mm + 縁石を足しても内側が反転しない)。離れた区間同士の最小間隔は約 440mm。

### 6.2 弧長ベースの走行

車両は曲線パラメータではなく弧長 `s` (mm) で進める。サンプル間隔が一定なので速度ムラが出ない。
`s` は無限に増え、参照時に `s mod 全長` を使う (周回リセット無し)。

### 6.3 速度プロファイル

`u(s) ∈ [0.3, 1]` を事前計算する。

1. 曲率から `u = clamp(sqrt(κ0/|κ|), 0.3, 1)`、`κ0 = 1/900mm`
2. 後ろ向きに走査して減速度上限を適用 (コーナー進入の減速)
3. 前向きに走査して加速度上限を適用 (脱出の加速)
4. 周回で値が合うよう 2 周分走査し、軽く平滑化

車速 = `設定の走行速度 × u(s)`。ストレートで最高速、ヘアピンで約半分になる。

## 7. 走行とドリフト

### 7.1 状態

`position, velocity, heading, travelDirection, driftAngle, speed, progress`。

- `travelDirection` = 速度ベクトルの向き
- `driftAngle` = 車体の向き − 進行方向。**`heading = travelDirection + driftAngle`**
- 進行方向と車体の向きは独立に持つ

### 7.2 ドリフト角

- 目標角: `β* = sign(κ_先読み) × g(|κ_先読み|) × 最大角 × min(強度, 1) × (0.65 + 0.35u)`
  - `g` は κ=1/1200 〜 1/250 の smoothstep。緩い曲がりでは浅く、ヘアピンでは深くなる
  - 先読み = 現在位置から `speed × 0.16s` 先 (進入の初期カウンターステア相当)
  - `β` の符号 = κ の符号。車体の鼻先がコーナーの内側を向く
- 実際の角度は 2 次ばね (ω, ζ) で追従する。強度が大きいほど ω が大きく ζ が小さい (キビキビ + 軽いオーバーシュート)
  - ストレートでは 0 に戻る (グリップ回復)
  - S 字では目標の符号が反転し、ばねが滑らかに反対側へ振る (振り返し)
  - 角度は絶対値でクランプ。急な角度ジャンプが出ない

### 7.3 位置

位置 = `センターライン(s) + 法線 × o`。`o` (横オフセット) は、ドリフト中にコーナー外側へ膨らむ量で、別のばねで追従する。
速度ベクトルは解析的に `T·ṡ·(1−κo) + N·ȯ` で求める (数値微分のノイズを避ける)。

## 8. カメラ

```
画面座標 = アンカー + k · Rot(−π/2 − heading) · (ワールド − 車両位置)
```

- 車両位置が常にアンカー (画面幅 × carX, 高さ × carY) に来る
- `heading` の方向が画面の上になる (回転は行列で表すので、±180° の折り返しで補間が破綻しない)
- ドリフト中は heading が進行方向とずれるので、路面が車体に対して斜めに流れる

## 9. 描画

### 9.1 テクスチャ

すべてプログラム生成のタイル (周期ノイズ)。**ワールド座標に固定した CanvasPattern** として塗るので、カメラが動いても模様が流れるだけでちらつかない。

| タイル | 実寸への割り当て | 内容 |
|---|---|---|
| asphalt | 1024px ↔ 200mm | 細かい粒、明暗の骨材、大きな色むら (焼き込み) |
| grass | 1024px ↔ 300mm | 芝の大きな色むら (焼き込み) + 草の筋 |
| gravel | 512px ↔ 100mm | ランオフの砂利 |

### 9.2 レイヤー順 (ワールド座標)

1. 芝
2. ランオフ (コーナー外側、先細り)
3. 縁石 (赤白、影とハイライトの線で立体感)
4. 路面 (外周と内周の 2 輪郭を even-odd で 1 回の fill)
6. ラバーライン (走行ラインの黒ずみ) とタイヤ痕
7. 路面端の白線、スタート/フィニッシュ (チェッカー)
8. (デバッグ時のみ) 車体輪郭と進行方向の矢印 — これだけは画面座標

### 9.3 タイヤ痕

実際の走行から記録する (`js/skids.js`)。

- 車両の固定ステップ (1/120s) ごとに、ドリフト角が最大角の 25% を超えていれば、左右の後輪の位置 (車両の長さ・幅の設定に追従) を折れ線の点として記録する。点の間隔は 5mm 以上
- 濃さは最大角に対する比で 3 段階 (25% / 55% / 80%)。段階が変わったら折れ線を区切る (最後の点から続けるので切れ目は出ない)
- 折れ線は 80 点ごとのチャンクに区切って保持し、各チャンクに走行距離 (s0, s1) を持たせる
- **3 周ぶんだけ残す**: 走行距離が「いまの走行距離 − 全長×3」より前のチャンクを、古い順に捨てる。周回で位置が戻っても、ループの継ぎ目で痕が不連続にならない。何周走っても量は一定
- 描画: チャンクが増減したときだけ、濃さの段階ごとの Path2D を作り直す。記録中の折れ線は毎フレーム直接描く (確保なし)
- 周回ごとに、ドリフト角 (±10%) と横位置 (±7mm) をわずかに変える (黄金比の数列)。完全に同じ軌跡の繰り返しだと、3 周ぶんの痕が 1 本に重なるため
- ラバーライン (走行ラインの黒ずみ) は、事前計算した固定の効果として残す (`js/marks.js`)。基準走行を 3 周ぶん回して中心の軌跡を作る。設定 (速度・最大角・強度・コース幅) が変わったときに作り直す

### 9.4 モーションブラー

シーンをオフスクリーンに描き、メインに `globalAlpha = 1 − blur` で重ねる (前フレームの残像)。`ctx.filter` は Safari 非対応なので使わない。
強度は設定で 0〜0.6、速度に応じて少し変える。

### 9.5 タイヤスモーク

- 量は設定で 0〜3 (既定 1)。粒の発生数は量に比例し、1 粒の不透明度は 0.85 を上限とする
- 後輪の位置 (車両の長さ・幅の設定に追従) から、ドリフト角がしきい値 (15°、最大角が小さいときはその半分) を超えている間だけ粒を出す。深いほど、速いほど、粒が多く濃く大きい
- 粒はワールド座標に固定。発生時に車の速度の 75% を引き継いで (空気に乗って) しばらく進み、空気抵抗で止まる。車体の外側へ 40〜130mm/s で広がる (実物の車体の脇に見えるように)
- 半径 5〜8mm → 17〜35mm に広がり、寿命 0.9〜1.9 秒で薄くなって消える
- 固定長のリングバッファ (最大 300 粒、毎フレームの確保なし)。描画は、ふわっとした円形のスプライト 1 枚を拡大縮小して重ね描き。視野の外は描かない
- 実物の車体は画面の手前にあるので、車体に隠れる部分と、車体に被さる表現はできない

### 9.6 明るさ

canvas 要素への CSS `filter: brightness()`。

### 9.7 性能

- 毎フレームの全画面の塗りは芝と路面の 2 回だけにする (色むらはタイルに焼き込む)。縁石の汚れ重ねは廃止
- `backdrop-filter` は使わない (毎フレーム更新される canvas の上で iOS が重くなる)
- フレームレートが 50fps を下回ったら描画解像度を自動で下げる (最小 ×0.5、localStorage に保存)

- 路面などは周期的に生成した大きな Path2D を使い回す。毎フレーム新しいオブジェクトは作らない
- 描画解像度の倍率 (0.5〜1) を設定に用意する。デバイスピクセル比は最大 2 に制限する
- 時間ベース: `dt` は 0.05s で打ち切り、車両は 1/120s の固定ステップで更新する

## 10. UI

- 端に寄せたボタン (左上: 設定 / 再生・停止 / UI 非表示)。車体が載る中央を避ける
- 設定パネルは右端に固定、タッチ操作向けの大きなスライダー
- UI 非表示中は画面の左右の端 (幅 28px) をタップすると再表示
- 実寸キャリブレーション: 100mm の線 + 微調整ボタンとスライダー。完了で線を消し、`pxPerMm` を保存
- 設定は localStorage (`mzvc.settings.v1`)。壊れた値は既定に戻す

設定項目: 走行速度 / 最大ドリフト角度 / ドリフト強度 / コーススケール / コース幅 / 車両表示 / 車両位置 X・Y / 路面の明るさ / 再生・停止 / UI 非表示 / リセット。
追加: モーションブラー、車両の長さ・幅 (デバッグ輪郭用)、描画解像度。

## 11. PWA / iPad

- `viewport-fit=cover`、`user-scalable=no`、`touch-action: none`、`overscroll-behavior: none`
- `apple-mobile-web-app-capable`、`black-translucent`、`apple-touch-icon`
- manifest: `display: standalone`、`orientation: portrait`、`start_url: "./"`、`scope: "./"`
- Service Worker: 相対パス、起動時にアプリ一式をプリキャッシュ、ネットワーク優先 (取得できたらキャッシュ更新、オフライン時はキャッシュ)。バージョン付きキャッシュ名
- Screen Wake Lock (対応環境のみ)。非対応は何もしない (既知の制約に明記)
- `visibilitychange` で時刻基準を取り直す (復帰時にジャンプしない)、Wake Lock を再取得
- リサイズ/回転で canvas を作り直す

## 14. リスクと対応

| リスク | 対応 |
|---|---|
| iPad の 60fps | 描画解像度の倍率、ブラー無効化を設定に用意。路面は 1 パスの fill で済ます |
| 路面タイルの繰り返しが目立つ | 異なるスケール/回転の色むら 2 枚で崩す |
| 非公開リポジトリで Pages が使えない | 失敗したら公開リポジトリへ切り替える (確認済みの方針) |
| ドリフトの見た目が不自然 | ばね係数を設定の「強度」で調整可能にする。実機確認は未検証として明記 |
